# BqLog 性能设计三篇

[English](PERFORMANCE_DESIGN.md) · [项目首页](../README_CHS.md)

BqLog 的快不是变魔术变出来的。这三篇文章从一行日志出发，把整套设计一步步推导出来：先给出最直观的方案，算清它的代价，再引出下一个。文章内容按 BqLog 2.5.0 的源码写成。

| 文章 | 讲了什么 |
|---|---|
| [一：从一行文本推导出压缩日志格式](<文章1_为何BqLog如此快 - 高性能实时压缩日志格式.MD>) | 文本怎么压掉：模板、VLQ、UTF-Mixed、分段与加密 |
| [二：从环形队列到自适应数据总线](<文章2_为何BqLog如此快 - 高并发环形队列.MD>) | 几十个线程怎么不打架：fetch_add + 回滚、MISO/SISO、Group、崩溃复盘 |
| [三：一次内存读取，能顺便做多少事情](<文章3_为何BqLog如此快 - 压缩日志执行路径优化.MD>) | 执行路径怎么省钱：融合拷贝哈希、模板缓存、长度回填、批量 I/O |

建议按顺序读。第一篇决定数据长什么样，第二篇决定数据怎么走，第三篇再把这条路上剩下的浪费一点点挤出来。

想看跑分就直接翻 [Benchmark](BENCHMARK_CHS.md)；想知道这些机制在日常使用里怎么配，看 [进阶用法](ADVANCED_USAGE_CHS.md)。
